# Plan: port seele to Rust (ADR 0002)

Status: implemented, cut-over pending (user sudo) · 2026-11-13 · Crate: `rust/` (binary `seele`) · Spec = the Python code plus the items below.

## Ground rules
- **Behaviour parity with Python.** The same `config.toml`, signal names (`docs/agents/collector-contract.md`), `/state` JSON shape (`signals`, `health`, `severity`) on 127.0.0.1:6743, and CLI (`run [--dry-run] [-c config] [-v]`, `identify [--hold s]`, `replay <fixture>`).
- **Scene parity is exact.** `seele replay tests/parity/fixture.json` must print JSON equal to `tests/parity/golden.json` (Python output). This is checked by a `cargo test`.
- `src/state.rs`, `src/sinks/mod.rs` (Sink trait, Frame), `src/collectors/mod.rs` and `Cargo.toml` are fixed interfaces. Only the orchestrator changes them.
- Never panic in collectors: log at most once a minute, set health, back off, retry.

## Parity gotchas
- Python `round()` is **round-half-to-even** (`round(0.5) == 0`, `round(2.5) == 2`). Use `f64::round_ties_even`. Both `colors.lerp` and `colors.scale` round, then `scale` clamps to 0..255.
- `ramp(x, stops)`: clamp x to 0..1. For consecutive stops, if `x <= p1`, lerp(c0, c1, (x-p0)/(p1-p0)); after the last stop, return the last colour.
- The scene drains events at the **start** of `render`. The traffic preview emits *after* draining, so those pulses appear on the next frame. Python's `random` isn't reproduced (preview only, outside parity).
- Pulse position: `(now-born)/pulse_seconds*(n+2w)-w`. Brightness `max(0, 1-|j-pos|/w)`. Additive saturating per channel.
- Alert flash: `int(now*6) % 2 == 0` while `now < alert_until`. The outage breath `0.2+0.8*(0.5+0.5*sin(t*2π/3))` overrides the flash.
- Breathing: `k = 1-depth+depth*sin(t*(speed+3*level)+i)`, where i is the zone index.
- Severity thresholds: outage if `gateway_down > 0.75 || containers_bad >= 0.5`; degraded if `gateway_down > 0.25 || containers_bad > 0.05 || any health != ok`.
- Quiet hours use local wall-clock `HH:MM-HH:MM` and wrap past midnight. Previews bypass them. Replay passes quiet = None.
- Replay sets signals directly (no EMA) and uses `now = t`, brightness 0.8, preview off. Output keys: `t`, `severity`, `frame` (string zone index → [[r,g,b],…]). Zones of size 0 are omitted.

## Work split (parallel subagents, disjoint files)
| Agent | Files |
|---|---|
| core | config.rs, colors.rs, scene.rs, replay.rs, debug_http.rs, sinks/terminal.rs, main.rs (run loop with 2 s config hot-reload, identify, replay), tests/parity.rs |
| openrgb | sinks/openrgb.rs: SDK client (protocol from `.venv/lib/python3.14/site-packages/openrgb/`), device wait (30 s), direct mode, per-zone update when changed |
| collectors | collectors/*.rs: host (sysinfo + k10temp file + nvml-wrapper), docker (bollard), traefik (`docker logs -f`), ollama, litellm (`docker exec psql`, read-only), gateway. Unit tests mirror tests/test_*.py |

## Cut-over
1. `cargo test` green, parity exact.
2. Run side by side: Python service live; Rust in `--dry-run` with the `/state` port overridable. Compare `/state` signals.
3. Swap `ExecStart` in `deploy/seele.service` to `rust/target/release/seele run`. Keep the Python tree until the remote-tier signals are verified.

## Result (2026-11-13)
- Built by 3 parallel Sonnet agents against a fixed `state.rs`, sink trait and dependency list. Integrated and reviewed by the orchestrator.
- **Scene parity exact:** 300/300 golden frames, checked independently. Tests: 26 unit + 7 ignored live checks (collectors, OpenRGB listing). Clippy clean after `--fix`.
- **Side by side** (Rust `--dry-run --state-port 6744` vs the Python service): same severity and health, the same 19 signals, all within 0.08. The Rust build also reports `host` health.
- **Resources:** Rust 0.3% of a core and 28 MB RSS, 6 MB binary. Python: about 1% and 69 MB.
- Fixed in review: a `Box::leak` in the docker collector (now static slices) and a stale `allow(dead_code)`.
- Not yet exercised: the OpenRGB sink in `run` mode for a long period (the live test only listed devices and wrote one zone). Verify right after the cut-over.
